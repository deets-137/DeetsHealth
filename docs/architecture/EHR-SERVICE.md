# DeetsHealth — The `ehr` service and its wire

> Designed 2026-10-21, before any code. The owner chose a Rust `ehr` service from the first
> call (BUILD-ORDER.md, Phase 1) and gRPC as its wire (§2). The rules it serves are
> [SECURITY.md](SECURITY.md) §4.4 (verification) and §4.9 (the model); the call path is
> [VOICE-AGENT.md](VOICE-AGENT.md) §8.1.

**Terms**
- **The agent:** the Python process. Pipecat, the Flow, the calls to Claude.
- **`ehr`:** the Rust process. The verify state, the patient binding, the scheduler, later the
  EHR adapters, sealing and the store.
- **The edge:** the one function on each side that turns a wire message into the side's own
  types, and back.
- **Handle:** an opaque, random token that names one call's session inside `ehr`.

## 1. What crosses the wire
The agent never holds a patient id. It holds a handle. `ehr` holds everything the handle
stands for: who the caller has proved to be, how many tries are left, the call's deadline.

```
agent                                    ehr
  OpenCall(call meta)            ──►     new session; returns a handle
  Identify(handle, name, dob)    ──►     one match: a code to the number on file (Phase 1: fake)
                                         the reply never says if one matched
  ResendCode(handle)             ──►     the code again; the reply never says if one went out
  CheckCode(handle, code)        ──►     PASS · FAIL · LOCKED, with tries left
  FindSlots(handle, wish)        ──►     slots, each with an opaque slot token; the wish's reason
                                         is kept for this call as the booking's note
  Book(handle, slot token, key)  ──►     the visit as booked (type, online, the reason sent as
                                         its note), or why not; `key` makes a retry safe
  CloseCall(handle)              ──►     session wiped (zeroized)
```
- **Every chart and booking call takes only the handle.** No message has a patient field. A
  call before both factors pass returns `PERMISSION_DENIED`. The Flow hides those tools too;
  `ehr` is the authority, the Flow is the second lock.
- **The check never echoes.** A failed `Identify` or `CheckCode` looks the same whatever the
  cause, so the replies cannot be used to learn who is a patient.
- **Slot tokens, not ids.** A slot token is valid for one handle and one call.
- **Errors carry a code from a fixed list, never text built from data.**

## 2. Why gRPC (the owner, 2026-10-21)
Speed was a tie: well under 5 ms a request on one machine, inside an 800 ms budget. gRPC won
on what matters when the EHR is slow on a live call:
- **Deadlines travel with the request.** `ehr` reads the time left and stops a slow fetch, so
  the agent can say a filler line or hand off.
- **A cancel reaches `ehr`.** When the caller interrupts (Phase 3), the agent cancels the
  request and the Rust handler stops. A `Book` is never cancelled half-way: it runs to the
  end or not at all, and its key makes a retry safe.
- **One source for the PHI tag** (§4).

Not chosen: HTTP with JSON. Its strict decoding is matched here by the edge (§5).

## 3. The contract
- One file, `ehr/proto/deets/ehr/v1/ehr.proto`, package `deets.ehr.v1`. `ehr` owns it; the
  agent generates from it.
- **Rust:** `tonic` and `prost`, generated in `ehr/build.rs`. `protoc` is Google's own release,
  pinned by SHA-256 in `ehr/protoc.json`. `scripts/protoc.mjs` fetches it once into `/.protoc/`
  (`npm run dev`, `npm run check` and `npm run db:test` run it first); `build.rs` stops with that
  command when it is missing, and when its version is not the pinned one. A deploy image names

- **Python:** `grpcio` with `grpc.aio` (the async API Pipecat needs), generated by
  `grpcio-tools`, which carries its own `protoc`, with type stubs (`--pyi_out`).

**Who is asking** (docs/architecture/ACCESS-ROLES.md §5, §8.1; built 2026-11-18, Hand-over 1). Every
RPC names what it needs in one table, `service.rs › RPC_LEVERS`; a test fails when an `rpc` has
no row. The person behind a staff request travels in the gRPC metadata `deets-actor` (their user
id), never in a message. `ehr` reads that person's levels from the store itself (`access.rs ›
actor`) and never takes levels from the agent. The needs:
- **Call** (`OpenCall` … `FileCall`): no person; a call is bound to its caller by its handle.
- **System** (`AdmitUser`, `SeedUsers`, `SeenOwner`): the agent on its own. `AdmitUser` and
  `SeenOwner` answer with the person's id, which the agent then sends as `deets-actor`.
- **Settings** (`ListSettingVersions`, `GetSettings`, `SaveSettings`): the lever by service
  (`settings.rs › lever`: voice and llm Vendors, prompt and system Agent, hospital Rules, roles
  Roles). With a person: View to read, Edit to save. With none: the agent itself (a call reading
  its settings, the prompt file synced, a Default seed), allowed and audited as the system.
- **Person** (`Levels`, `LogAccess`): any person on the list.
- **A lever and level** for the rest (Testing, People, Roles, Audit logs, Rules).

A refusal is `PERMISSION_DENIED` with fixed words ("needs people view", or the rule's line) and
an audit row. The roles list itself is the settings service `roles` (`Get`/`SaveSettings`), not
RPCs of its own: it is versioned like every other service, and a save is checked by
`access.rs › may_save_roles` in the same transaction. Every change writes its audit row in the
same transaction as the change (`audit.rs`; ACCESS-ROLES.md §5.1). Until the agent sends
`deets-actor` (Hand-over 2), every staff RPC from the console is refused.

`FileTestRun`, `AddAnnotation` and `ListAnnotations` are the kept scripts' runs and the
annotations in the call store (DATABASE.md §8, §9): no handle; `FAILED_PRECONDITION` without a
store. A failure line and an annotation's words are marked `(phi)`. `OpenCall` takes the call's
`data_class` (DATABASE.md §7.5): a synthetic call reaches only a sandbox, a real call only a
production EHR, and `FileCall` files a record in the class its `call_start` names.

The three settings RPCs are the settings store (CONSOLE.md §7.3; `ehr/src/settings.rs`): no
handle, no protected data, `FAILED_PRECONDITION` when `ehr` runs without a store.

`ImportPlaces` is Config › Hospital › Places, Import from Epic (HOSPITAL-CONFIG.md §8): no
handle, no protected data (a place is a fact about the hospital). It searches Epic's directory
(`epic_ehr.rs › EpicEhr::places`) and answers with the hospital's rows; it saves nothing.
`FAILED_PRECONDITION` when `ehr` does not serve Epic's sandbox. The message limit is 4 MiB each
way (`main.rs › MESSAGE_LIMIT`, gRPC's own default; 64 KB until 2026-11-15), so a whole
hospital's places fit in one `GetSettings`.

The five user RPCs are the People list (ops/DEMO.md §3.5; `ehr/src/users.rs`, migration 0007):
who may sign in to the console. No handle. A staff member's email and name are not patient
data, but the contract marks them (`phi`), so they never reach a log; the store seals both and
finds a row by a keyed hash of the email (`SealKey::lookup`, a key made from the data key by
HKDF). `FAILED_PRECONDITION` without a store; the other errors are fixed words that name a field,
never a value. The owner is never removed (`PERMISSION_DENIED`); a removal keeps the row.

## 4. The PHI tag
```proto
extend google.protobuf.FieldOptions { bool phi = 50001; }   // 50000+ is for in-house use

message IdentifyRequest {
  string handle = 1;
  string name   = 2 [(phi) = true];
  string dob    = 3 [(phi) = true];
}
```
One mark, read in three places:
- **Rust, at build time.** `build.rs` reads the descriptors. Every message with a tagged field
  loses its derived `Debug` (`prost`'s `skip_debug`) and gets one that prints `***` for the
  tagged fields. A `{:?}` can no longer leak.
- **Python, at run time.** The log redactor (SECURITY.md §4.5) walks any protobuf message in a
  log record and blanks each field whose options carry `phi`. Python prints a message as plain
  text with every field, so this is not optional.
- **A test, both sides.** It lists every tagged field and fails if one has no edge conversion
  into a wrapper type.

## 5. The edge
Protobuf has no required fields: a missing value arrives as `""` or `0`, and an unknown field
is ignored. So nothing past the edge sees a wire type.
- **Rust:** each request converts by `TryFrom` into a domain type. An empty handle, a bad
  date, an empty code: rejected with `INVALID_ARGUMENT` before any logic runs. A birth date
  must be a real calendar day, from 1900 to tomorrow in UTC; it is refused here, before the
  session counts one of the caller's three tries (2026-11-11). Tagged fields go
  straight into `Shielded<T>`. `Shielded<T>` has no `Serialize`, so each reply that carries a
  protected value reveals it in one named function, easy to review.
- **Python:** each reply converts into the agent's own dataclasses. Tagged fields become a
  wrapper that prints `***`. Only the code that hands words to Claude or to the voice opens it.

## 6. Transport
> **Part:** designed · 2026-10-21 · the owner: FIPS crypto at both ends

- **mTLS, TLS 1.3 only, from the first day, on this PC too.** A script makes a dev CA and two
  certificates (`ehr`, `agent`) into the git-ignored `dev-certs/`. `ehr` accepts only the
  `agent` certificate; the agent accepts only the `ehr` one. One code path from dev to deploy.
- **FIPS 140-validated crypto at both ends** (the owner, 2026-10-21; the standard still holds,
  SECURITY.md §4). Not chosen: a local socket with no network, which ties the two processes
  to one machine for good.
  - **`ehr`:** `rustls` on AWS-LC. The deploy build turns on the `fips` feature (AWS-LC's FIPS
    module). With `DEETS_REQUIRE_FIPS=1` set, `ehr` refuses to start unless its TLS
    configuration reports FIPS mode.
  - **The agent:** `grpcio` built from source against the deploy image's FIPS-validated
    OpenSSL, not the wheel's bundled BoringSSL.
  - **On this PC:** the same libraries without FIPS mode, because the FIPS builds need extra
    tools on Windows. The FIPS switch is the one difference between dev and deploy.
  - To confirm before the first deploy (Phase 6): the AWS-LC certificate number and the
    `grpcio` source build in the image.
- **The port is never hard-coded.** The dev launcher picks a free port on `127.0.0.1` and gives
  it to both processes.
- **One HTTP/2 connection, opened when the agent starts**, so no handshake falls inside a call.
  The standard gRPC health check tells the agent `ehr` is up.
- Limits: a small maximum message size and a bounded number of streams.

## 6a. As built (2026-10-21)
> **Part:** built · 2026-10-21. Where this disagrees with the design above, this is the code.

- **`ehr/`** is a member of the Cargo workspace (`deetshealth-ehr`), with `tonic` and `prost`
  0.14. The binary is `deetshealth-ehr` (`--bind`, default 127.0.0.1; `--port`, default 0, so
  the OS picks and the first stdout line names it; `--certs`, default `dev-certs`).
- **`OpenCall`'s reply** carries the call's verification limits in full (`identifies_left`,
  `resends_left`, `code_tries_left`, from the `MAX_*` constants), counts only, so a reader
  (the Chat page's Step panel, CHAT.md §11) never copies them (2026-11-12).
- **`OpenCall`'s request** names the EHR the call reads (`ehr`: local, or Epic's sandbox in
  dev; EPIC.md §5.2). It names a server, never a patient; the session keeps it for the call.
  The Epic adapters are `ehr/src/epic_ehr.rs`, with the sixth pass, `EhrPass`, held to that
  file (2026-11-12). Since 2026-11-13 it also names the call's `prompt_version` (a version id,
  never words): `ehr` reads that version's `text.code` once and texts the code with it; 0 uses
  the prompt file compiled into `ehr` (CONSOLE.md §9.3). Since 2026-11-14 it also names the
  call's `system_version` (a version id, never values): `ehr` fills that version's System
  variables into `text.code` when the call opens, and `{code}` when the text goes out
  (`settings.rs › fill`, one pass each); 0 uses the active version, or `agent/prompts/VARIABLES.md`
  compiled into `ehr` when the store has none (SYSTEM-PAGE.md §3.4).
- **`OpenCall` takes the call's hospital** (2026-11-15, [HOSPITAL-CONFIG.md](HOSPITAL-CONFIG.md)):
  `ehr` reads the active `hospital` version once (`service.rs › call_hospital`) and keeps it in
  the session; every adapter call of that call reads it (`Scheduler`'s `h`). The reply adds
  `times_of_day` (the names `FindSlots` may send) and `hospital_version` (the label, or "file"
  with no store). `FindSlots` looks the time of day up in the call's own copy, so a save during
  a call changes nothing in it.
- **`SaveSettings` checks the two services together** (2026-11-14, SYSTEM-PAGE.md §3.3): a
  `prompt` save is refused when a section holds a `{name}` that is neither its own code value
  nor a System variable of the active `system` version; a `system` save is refused when the
  active words still use a variable it removes. The message names a section and a variable,
  never a value or the words.
- **`Visit`** carries what the visit is (2026-11-13): `visit_type` and `reason` (both marked
  `phi`), `online`, and `reason_private`. Each adapter builds a `VisitAbout`
  (`ehr/src/visit_about.rs`) from the record's plain words; a sensitive type or reason is
  dropped there, so it never crosses the wire, and `reason_private` is set
  (FUTURE-SETTINGS.md §9).
- **The contract** has eight calls: `OpenCall`, `CloseCall`, `Identify`, `ResendCode`,
  `CheckCode`, `FindSlots`, `Book`, `FindVisit` (S5: the soonest visit, or one the caller
  names; it replaced `NextVisit` on 2026-11-14, EPIC.md §7.10). There is no separate `SendCode`: `Identify` sends the first
  code when one patient matches. No test or flag can mark a session verified; every test
  walks `Identify` and `CheckCode`.
- **Verification** (`verify.rs`): the `Patients` trait returns candidates; the match is ours
  (`one_match`): the same birth date, and the given and family names each equal or one letter
  off when 5 letters or more (`Shielded::same_name` in core, which answers yes or no without a
  reveal). Two matches count as none. Limits per call: 3 `Identify`, 2 resends, 3 wrong
  codes, then `LOCKED` for the rest of the call. A code lasts 10 minutes. A new `Identify`
  drops the old code.
- **The fakes:** four synthetic patients (two of them near-identical on one date, to prove the
  refusal), phone numbers in the 555-01xx range no real phone uses, and the fixed code
  `246810`, so a typed call can use it and the replay cache stays valid. Nothing is sent. The
  patients and their visits are in `ehr/fixtures/sandbox.json` (`sandbox.rs`), which the
  Chat page shows too (CHAT.md §8).
- **The code by text** (`texts.rs`, 2026-11-12): when `DEETS_TWILIO_ACCOUNT_SID` and its
  partners are set, `ehr` makes a random code and sends it with Twilio's Messages API request
  (rustls on the wire's AWS-LC provider, Mozilla's roots, 5 s). In dev it goes to the fake
  Twilio in the agent's dev server; from Phase 5 to Twilio itself. The text's words are
  AGENT-PROMPT.md › `text.code`. Only `texts.rs` holds a `TextPass` (core/src/text.rs), the
  pass that reveals the number and the code for the request; a test enforces it. The whole
  path: TEXTS.md.
- **Booking runs in its own task.** A dropped request (the caller interrupts, a deadline
  passes) cannot cut it off half-way; the answer is kept under its key for the retry.
- **The transport** (`transport.rs`): `rustls` 0.23 on AWS-LC, TLS 1.3 only, ALPN `h2`; the
  client must hold a certificate from the CA, for client use. A handshake over 5 seconds is
  dropped. tonic serves the TLS streams and builds no TLS config of its own. Limits: 10
  seconds a request unless the agent's deadline is shorter, 64 requests at once per
  connection, 64 KB a message. The gRPC health service is on.
- **FIPS:** the `fips` feature turns on AWS-LC's FIPS module; it needs CMake and Go, so
  `cargo check --all-features` fails on this PC by design. With `DEETS_REQUIRE_FIPS=1` the
  binary refuses TLS that is not in FIPS mode, and, in this phase, refuses to start at all,
  because it holds the fakes only.
- **Dev certificates:** `cargo run -p deetshealth-ehr --example dev_certs` writes a CA and the
  `ehr` and `agent` certificates (ECDSA P-256) to `dev-certs/`. The CA's key is never written.
  `ehr`'s certificate is for serving only, the agent's for connecting only.
- **`tests/transport.rs`** starts the real server on a free port with fresh certificates: the
  agent's certificate gets in, no certificate is refused, `ehr`'s certificate as a client is
  refused.
- **Two marks, not one:** `(phi)` for protected data and `(secret)` for credentials (the
  handle, the slot token). Both are redacted the same way. A marked field must be a string
  and may not sit in a oneof; a message may not nest another. `build.rs` refuses each.
- **`build.rs` walks the descriptor bytes itself**, because `prost-types` drops the unknown
  extensions that carry the marks. It writes `redacted.rs`: the `Debug` of each marked
  message, the list `MARKED_FIELDS`, and a test that fills each marked field with a canary and
  checks no debug print shows it.
- **The wire pass:** `core/src/wire.rs` adds `WirePass`, the fourth pass of `Shielded<T>`.
  Only `ehr/src/edge.rs` may name it; a test reads every file in `ehr/src/` to enforce that.
- **Sessions:** a 128-bit random handle from the OS; a lock per session, so a slow booking on
  one call never holds another; at most 10,000 open; one left open is wiped after 3 hours. A
  wrong handle and a closed call get the same reply.
- **Slots:** at most 3 per `FindSlots` (enough to choose from, short enough to say). New
  tokens each time, so an old token no longer books. A token works on its own call only.
  `visit_mode` (2026-11-14; the owner's 1A of 2026-11-13): in person, online, or either when
  unset; an unknown value is `INVALID_ARGUMENT`. Each slot says whether it is online. Since
  2026-11-16 ehr keeps only the returned times that fit the mode asked, on every page: an EHR
  may return a type other than the one searched (Epic's sandbox returns every time as a video
  visit), so an in-person ask there now finds no times.
  New or established (2026-11-16; BOOKING-RULES.md §5.1): when a visit type the agent may book
  is for one kind of patient, the first `FindSlots` of a call reads the caller's seen visits in
  the hospital's window (`Session.seen`, one call long), and every page keeps only the slots
  whose type fits the caller at the slot's place (`keep_fitting`). No wire change.
  The usual place, the PCP and P-A (2026-11-16; BOOKING-RULES.md §5.2): `FindSlotsRequest.any_place`
  turns the usual place off; a new search held to it says so in `FindSlotsReply.place_default`
  (phi); each `Slot` says `with_pcp` and `sooner`. The PCP comes from verification (`Session.pcp`).
  The place and the specialty (2026-11-16; BOOKING-RULES.md §5.3): `FindSlotsRequest.place` and
  `.specialty` (phi), the caller's words, matched in Rust (`Hospital::pick`); `plan_only` says
  where a search would look and searches nothing. When no search ran, `FindSlotsReply.place_ask`
  says which question to ask (`places`, phi, names the places). `FindVisitRequest.place` (phi)
  narrows a visit by its place; `FindVisitReply.unknown_place` says the words name none.
  The Booking rules (2026-11-16; §5.5): `FindSlotsReply.rule` when a rule held back every time;
  `BookReply.check_referral` when the booked time's rule says Book and flag.
- **Where to go (2026-11-16; BOOKING-RULES.md §5.4):** `PlaceInfo(handle, place)` answers from
  the call's hospital only: a place's name, address and phone (phi: tied to the caller's
  question), its hours and the hospital's next closed days. An open handle is enough: it reads
  no record, so it works before verification.
- **The reason becomes the booking's note (2026-11-14).** `FindSlots`'s reason (the caller's
  own words: the agent checks them, CALL-FLOW.md §5) is screened at the edge
  (`BookNote::screen`, `visit_about.rs`), before it is wrapped, and kept in the session one call
  long (`Session.note`, the last `FindSlots`'s). `Book` passes it to the adapter
  (`Scheduler::book(patient, slot, note)`): the fake keeps it on the booked visit; Epic's `$book`
  will send it as `appointmentNote` (E-4, EPIC.md §5.2). The words go to the scheduler even when
  they name sensitive care; the screen governs only what the agent may say back.
- **Booking:** the idempotency key is 16 to 128 of `[A-Za-z0-9_-]`. A retry with the same key
  gets the same answer; the same key for another slot is refused. `BookReply.visit` is the visit
  as booked (`edge::visit`): its type, whether it is online, and the reason, after the screen
  (`VisitAbout::booked`; a sensitive type or reason makes it private). `BookReply.booked` (the
  slot) stays for older agents.
- **The fake scheduler:** six fixed slots, 2026-11-02 to 2026-11-06, two synthetic clinicians
  at one synthetic clinic, each with a visit type as Epic names them: four "Office Visit" (in
  person; the first three, so a list for "either" reads as before) and two "Video Visit"
  (online). No clock. It filters by day with `Shielded`'s comparison, without a reveal, and by
  `visit_mode`.
- **The Python side** is built: AGENT.md.
- **The code check is constant time** (2026-11-12, the owner's ask): `CheckCode` compares with
  `Shielded::ct_eq` (the `subtle` crate), so a reply's timing never says how many digits were
  right. The lock after three wrong codes already made a timing attack impractical; this
  closes it.
- **Not built yet:** tracing.

## 7. Tracing and tests
- **The call timeline:** the OpenTelemetry trace context rides in gRPC metadata, so one call is
  one trace across both processes. Spans carry the RPC name, the duration and the status code;
  never a field value.
- **`ehr` is deterministic in tests:** fixed fake patients, fixed open slots, a fixed clock. A
  tool result that changes changes the prompt, and a changed prompt misses the replay cache
  and spends tokens (the $100 budget, BUILD-ORDER.md Phase 1).
- **The gate test** (`agent/tests/test_gate.py`) runs the real `ehr` with its fakes and no
  model. It walks the Flow and checks which tools each node offers, and that every chart call
  before verification returns `PERMISSION_DENIED`.
- **Rust unit tests** cover the session's states: open, identified, code sent, verified,
  locked, closed.

## 7a. Panics
> **Part:** designed · 2026-11-14 · not built. Fork test: 0 real forks (each choice below had
> one option left).

**The gap (read 2026-11-14).** `ehr` installs no panic hook. Rust's default hook writes the
panic message, with its file and line, to stderr. `Shielded<T>` cannot be formatted, so a value
in the wrapper cannot reach a message. But an `unwrap()` or `expect()` on a library's error
prints that error's text. A Postgres error can name a row's value ("Key (…)=(…) already
exists"). A `reqwest` error names its URL, and an Epic URL carries the patient id in its
query. In dev, stderr goes to the terminal. In a deploy, it goes to the cloud's log, outside
the wall (SECURITY.md §4.5).

**The design.**
1. **One hook, in the core crate:** `deetshealth_core::panic::install()`. `ehr` calls it first
   in `main`, before any subcommand (`ingest` and the Epic probes too). The patient app's hook
   (archived `src-tauri/src/log.rs`) is the model.
2. **The hook writes one fixed line:** the thread's name and the file and line of the panic,
   and "the message is withheld". It does not call the default hook. A backtrace, when
   `RUST_BACKTRACE` is set, names frames only, never a value, so it stays.
3. **A panic fails one request, never the server.** Each RPC's body runs under a guard. A
   panic becomes `INTERNAL` with fixed text. The agent maps it to its fixed failure line
   (`ehr_client.py`, `ErrorKind.OTHER`). The other calls on the same connection go on.
4. **A panic in a call's request closes that call's session.** The guard knows the handle. It
   closes the session as `CloseCall` does: it wipes the secrets, and every later request with
   that handle is `UNAUTHENTICATED`. The agent then offers the caller a person. Reason: a
   panic between two steps of the verify state (for example, after a code is sent and before
   a wrong try is counted) must never let a caller skip a limit. A panic is a bug, so this
   costs the caller a hand-off only when a bug fires.
5. **A test that stays:** an integration test in `ehr/tests/` installs the hook with a
   buffer in place of stderr, panics on a thread with a marker string, and checks that the
   marker is not in the buffer. A second test makes a handler panic and checks the reply is
   `INTERNAL`, the session is closed, and the next request on the same channel succeeds.

**What this does not change.** The fake scheduler's `std::sync::Mutex` (`scheduler.rs`) is
poisoned by a panic while it is held, and every later `lock().unwrap()` panics too. That fails
closed, and the fake is dev only. The real adapters hold no `std` lock across a request.

**Each place it runs.**
- **The call:** a panic ends the chart path for that one call; the caller gets a person. Other
  calls go on.
- **The console:** not touched. Settings and people requests carry no handle; a panic there
  fails that request only.
- **The deploy (A2 and B):** the hook is in the binary, so both get it. The line it writes
  carries no value, so the cloud's log may keep it.
- **Each EHR:** the hook covers every adapter, because it is process wide.
