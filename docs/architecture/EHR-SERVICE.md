# DeetsHealth — The `ehr` service and its wire

> Designed 2026-10-21, before any code. The owner chose a Rust `ehr` service from the first
> call (BUILD-ORDER.md, Phase 1) and gRPC as its wire (§2). The rules it serves are
> [SECURITY.md](SECURITY.md) §4.4 (verification) and §4.9 (the model); the call path is
> [VOICE-AGENT.md](VOICE-AGENT.md) §8.1.

**Terms**
- **The agent:** the Python process. Pipecat, the Flow, the calls to Claude.
- **`ehr`:** the Rust process. The verify state, the patient binding, the scheduler, later the
  EHR adapters, sealing and the store.
- **The edge:** the one function on each side that turns a wire message into the side's own
  types, and back.
- **Handle:** an opaque, random token that names one call's session inside `ehr`.

## 1. What crosses the wire
The agent never holds a patient id. It holds a handle. `ehr` holds everything the handle
stands for: who the caller has proved to be, how many tries are left, the call's deadline.

```
agent                                    ehr
  OpenCall(call meta)            ──►     new session; returns a handle
  Identify(handle, name, dob)    ──►     one match: a code to the number on file (Phase 1: fake)
                                         the reply never says if one matched
  ResendCode(handle)             ──►     the code again; the reply never says if one went out
  CheckCode(handle, code)        ──►     PASS · FAIL · LOCKED, with tries left
  FindSlots(handle, wish)        ──►     slots, each with an opaque slot token
  Book(handle, slot token, key)  ──►     booked, or why not; `key` makes a retry safe
  CloseCall(handle)              ──►     session wiped (zeroized)
```
- **Every chart and booking call takes only the handle.** No message has a patient field. A
  call before both factors pass returns `PERMISSION_DENIED`. The Flow hides those tools too;
  `ehr` is the authority, the Flow is the second lock.
- **The check never echoes.** A failed `Identify` or `CheckCode` looks the same whatever the
  cause, so the replies cannot be used to learn who is a patient.
- **Slot tokens, not ids.** A slot token is valid for one handle and one call.
- **Errors carry a code from a fixed list, never text built from data.**

## 2. Why gRPC (the owner, 2026-10-21)
Speed was a tie: well under 5 ms a request on one machine, inside an 800 ms budget. gRPC won
on what matters when the EHR is slow on a live call:
- **Deadlines travel with the request.** `ehr` reads the time left and stops a slow fetch, so
  the agent can say a filler line or hand off.
- **A cancel reaches `ehr`.** When the caller interrupts (Phase 3), the agent cancels the
  request and the Rust handler stops. A `Book` is never cancelled half-way: it runs to the
  end or not at all, and its key makes a retry safe.
- **One source for the PHI tag** (§4).

Not chosen: HTTP with JSON. Its strict decoding is matched here by the edge (§5).

## 3. The contract
- One file, `ehr/proto/deets/ehr/v1/ehr.proto`, package `deets.ehr.v1`. `ehr` owns it; the
  agent generates from it.
- **Rust:** `tonic` and `prost`, generated in `ehr/build.rs`. `protoc` comes from a vendored
  crate, so nothing is installed by hand.
- **Python:** `grpcio` with `grpc.aio` (the async API Pipecat needs), generated by
  `grpcio-tools`, which carries its own `protoc`, with type stubs (`--pyi_out`).
- A breaking change gets a new package (`v2`); fields are never renumbered.

## 4. The PHI tag
```proto
extend google.protobuf.FieldOptions { bool phi = 50001; }   // 50000+ is for in-house use

message IdentifyRequest {
  string handle = 1;
  string name   = 2 [(phi) = true];
  string dob    = 3 [(phi) = true];
}
```
One mark, read in three places:
- **Rust, at build time.** `build.rs` reads the descriptors. Every message with a tagged field
  loses its derived `Debug` (`prost`'s `skip_debug`) and gets one that prints `***` for the
  tagged fields. A `{:?}` can no longer leak.
- **Python, at run time.** The log redactor (SECURITY.md §4.5) walks any protobuf message in a
  log record and blanks each field whose options carry `phi`. Python prints a message as plain
  text with every field, so this is not optional.
- **A test, both sides.** It lists every tagged field and fails if one has no edge conversion
  into a wrapper type.

## 5. The edge
Protobuf has no required fields: a missing value arrives as `""` or `0`, and an unknown field
is ignored. So nothing past the edge sees a wire type.
- **Rust:** each request converts by `TryFrom` into a domain type. An empty handle, a bad
  date, an empty code: rejected with `INVALID_ARGUMENT` before any logic runs. Tagged fields go
  straight into `Shielded<T>`. `Shielded<T>` has no `Serialize`, so each reply that carries a
  protected value reveals it in one named function, easy to review.
- **Python:** each reply converts into the agent's own dataclasses. Tagged fields become a
  wrapper that prints `***`. Only the code that hands words to Claude or to the voice opens it.

## 6. Transport
> **Part:** designed · 2026-10-21 · the owner: FIPS crypto at both ends

- **mTLS, TLS 1.3 only, from the first day, on this PC too.** A script makes a dev CA and two
  certificates (`ehr`, `agent`) into the git-ignored `dev-certs/`. `ehr` accepts only the
  `agent` certificate; the agent accepts only the `ehr` one. One code path from dev to deploy.
- **FIPS 140-validated crypto at both ends** (the owner, 2026-10-21; the standard still holds,
  SECURITY.md §4). Not chosen: a local socket with no network, which ties the two processes
  to one machine for good.
  - **`ehr`:** `rustls` on AWS-LC. The deploy build turns on the `fips` feature (AWS-LC's FIPS
    module). With `DEETS_REQUIRE_FIPS=1` set, `ehr` refuses to start unless its TLS
    configuration reports FIPS mode.
  - **The agent:** `grpcio` built from source against the deploy image's FIPS-validated
    OpenSSL, not the wheel's bundled BoringSSL.
  - **On this PC:** the same libraries without FIPS mode, because the FIPS builds need extra
    tools on Windows. The FIPS switch is the one difference between dev and deploy.
  - To confirm before the first deploy (Phase 6): the AWS-LC certificate number and the
    `grpcio` source build in the image.
- **The port is never hard-coded.** The dev launcher picks a free port on `127.0.0.1` and gives
  it to both processes.
- **One HTTP/2 connection, opened when the agent starts**, so no handshake falls inside a call.
  The standard gRPC health check tells the agent `ehr` is up.
- Limits: a small maximum message size and a bounded number of streams.

## 6a. As built (2026-10-21)
> **Part:** built · 2026-10-21. Where this disagrees with the design above, this is the code.

- **`ehr/`** is a member of the Cargo workspace (`deetshealth-ehr`), with `tonic` and `prost`
  0.14. The binary is `deetshealth-ehr` (`--bind`, default 127.0.0.1; `--port`, default 0, so
  the OS picks and the first stdout line names it; `--certs`, default `dev-certs`).
- **The contract** has eight calls: `OpenCall`, `CloseCall`, `Identify`, `ResendCode`,
  `CheckCode`, `FindSlots`, `Book`, `NextVisit` (S5: the soonest visit, from fixed fake visits
  and this run's bookings). There is no separate `SendCode`: `Identify` sends the first
  code when one patient matches. No test or flag can mark a session verified; every test
  walks `Identify` and `CheckCode`.
- **Verification** (`verify.rs`): the `Patients` trait returns candidates; the match is ours
  (`one_match`): the same birth date, and the given and family names each equal or one letter
  off when 5 letters or more (`Shielded::same_name` in core, which answers yes or no without a
  reveal). Two matches count as none. Limits per call: 3 `Identify`, 2 resends, 3 wrong
  codes, then `LOCKED` for the rest of the call. A code lasts 10 minutes. A new `Identify`
  drops the old code.
- **The fakes:** four synthetic patients (two of them near-identical on one date, to prove the
  refusal), phone numbers in the 555-01xx range no real phone uses, and the fixed code
  `246810`, so a typed call can use it and the replay cache stays valid. Nothing is sent.
- **Booking runs in its own task.** A dropped request (the caller interrupts, a deadline
  passes) cannot cut it off half-way; the answer is kept under its key for the retry.
- **The transport** (`transport.rs`): `rustls` 0.23 on AWS-LC, TLS 1.3 only, ALPN `h2`; the
  client must hold a certificate from the CA, for client use. A handshake over 5 seconds is
  dropped. tonic serves the TLS streams and builds no TLS config of its own. Limits: 10
  seconds a request unless the agent's deadline is shorter, 64 requests at once per
  connection, 64 KB a message. The gRPC health service is on.
- **FIPS:** the `fips` feature turns on AWS-LC's FIPS module; it needs CMake and Go, so
  `cargo check --all-features` fails on this PC by design. With `DEETS_REQUIRE_FIPS=1` the
  binary refuses TLS that is not in FIPS mode, and, in this phase, refuses to start at all,
  because it holds the fakes only.
- **Dev certificates:** `cargo run -p deetshealth-ehr --example dev_certs` writes a CA and the
  `ehr` and `agent` certificates (ECDSA P-256) to `dev-certs/`. The CA's key is never written.
  `ehr`'s certificate is for serving only, the agent's for connecting only.
- **`tests/transport.rs`** starts the real server on a free port with fresh certificates: the
  agent's certificate gets in, no certificate is refused, `ehr`'s certificate as a client is
  refused.
- **Two marks, not one:** `(phi)` for protected data and `(secret)` for credentials (the
  handle, the slot token). Both are redacted the same way. A marked field must be a string
  and may not sit in a oneof; a message may not nest another. `build.rs` refuses each.
- **`build.rs` walks the descriptor bytes itself**, because `prost-types` drops the unknown
  extensions that carry the marks. It writes `redacted.rs`: the `Debug` of each marked
  message, the list `MARKED_FIELDS`, and a test that fills each marked field with a canary and
  checks no debug print shows it.
- **The wire pass:** `core/src/wire.rs` adds `WirePass`, the fourth pass of `Shielded<T>`.
  Only `ehr/src/edge.rs` may name it; a test reads every file in `ehr/src/` to enforce that.
- **Sessions:** a 128-bit random handle from the OS; a lock per session, so a slow booking on
  one call never holds another; at most 10,000 open; one left open is wiped after 3 hours. A
  wrong handle and a closed call get the same reply.
- **Slots:** at most 3 per `FindSlots` (enough to choose from, short enough to say). New
  tokens each time, so an old token no longer books. A token works on its own call only.
- **Booking:** the idempotency key is 16 to 128 of `[A-Za-z0-9_-]`. A retry with the same key
  gets the same answer; the same key for another slot is refused.
- **The fake scheduler:** six fixed slots, 2026-11-02 to 2026-11-06, two synthetic clinicians
  at one synthetic clinic. No clock. It filters by day with `Shielded`'s comparison, without a
  reveal.
- **The Python side** is built: AGENT.md.
- **Not built yet:** tracing, a constant-time code comparison (the agent is the only client,
  behind mTLS).

## 7. Tracing and tests
- **The call timeline:** the OpenTelemetry trace context rides in gRPC metadata, so one call is
  one trace across both processes. Spans carry the RPC name, the duration and the status code;
  never a field value.
- **`ehr` is deterministic in tests:** fixed fake patients, fixed open slots, a fixed clock. A
  tool result that changes changes the prompt, and a changed prompt misses the replay cache
  and spends tokens (the $100 budget, BUILD-ORDER.md Phase 1).
- **The gate test** (`agent/tests/test_gate.py`) runs the real `ehr` with its fakes and no
  model. It walks the Flow and checks which tools each node offers, and that every chart call
  before verification returns `PERMISSION_DENIED`.
- **Rust unit tests** cover the session's states: open, identified, code sent, verified,
  locked, closed.

## 8. Open
Nothing open. Decided 2026-10-21 by the owner:
- **The TLS library:** FIPS-validated crypto at both ends (§6).
- **How the caller is identified:** by name and date of birth, then the code (SECURITY.md
  §4.4). Not chosen: the calling number first, with name and date of birth as the fallback
  (one question fewer, but it needs a phone search in each EHR).
